01 / OBSERVE / POSITIONING + ORBITAL SYSTEMS
HORIZON Observatory
OBSERVATION → STATE → PROPAGATION
An Android scientific observatory built around a strict boundary between what the device observes and what software derives. Horizon acquires raw GNSS measurements, satellite status and navigation messages alongside cellular, sensor and PVT evidence; carries source timestamps, monotonic ingestion time, session-scoped sequence numbers and provenance through a reliable persistence queue into Room; then exposes integrity audit, semantic normalization, analysis, replay and verified export without destroying the original evidence. A separate orbital domain ingests catalog/OMM data behind a propagation contract and an OrbitCore-backed SGP4/SDP4 path, with deep-space handling, reference-frame transforms, observer/topocentric geometry, visibility and pass prediction, while keeping orbital prediction separate from observed GNSS truth. The resilience layer can combine GNSS, IMU/orientation, cellular/network evidence, last trusted navigation state and validated prediction while keeping observed, derived, predicted and dead-reckoned states explicitly distinct.

02 / ENGINEERING GRAMMAR

The interfaces change. The discipline does not.

Evidence before inference.Observed data, derived state and interpretation are separate layers. Claims earn their confidence through receipts.
Provenance is part of the product.Where a value came from, when it was observed, and how it was transformed should remain inspectable.
Failure boundaries stay visible.Missing hardware, uncertain mappings, synthetic inputs and unavailable evidence are represented—not disguised.
